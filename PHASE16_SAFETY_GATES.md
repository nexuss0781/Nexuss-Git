# Phase 16: Safety Gates and Action Previews

Nexuss-Git now previews repository mutations before execution. The preview is generated by the same local controller that performs the operation, so the browser reviews the current repository state rather than a client-side guess.

## Preview contract

The local API exposes:

```text
POST /api/preview
```

The request contains an operation name and operation inputs. The response describes the operation, human-readable summary, impact lines, whether confirmation is required, whether the operation is allowed, and an optional denial reason.

| Operation | Preview behavior | Confirmation |
|---|---|---|
| `branch.create` | Shows the branch that will be created and selected | Not required |
| `branch.switch` | Shows the target branch | Not required |
| `stage` | Shows the number of paths to stage | Not required |
| `unstage` | Shows the number of paths to remove from the index | Not required |
| `commit` | Shows the staged path count and validates the commit message | Required |
| `push` | Shows the branch and remote that would receive the push | Required |

Push previews deny protected branches (`main`, `master`, `production`, and `release`) before a mutation can be attempted. Commit previews deny empty messages and commits with no staged paths.

## Browser behavior

The commit and push buttons first request a preview, display the proposed impact through a confirmation dialog, and only call the mutation endpoint after explicit confirmation. If a preview denies the operation, the mutation is never sent. If a mutation fails, the browser retains its current input and shows the returned error.

## Audit integration

Every preview is recorded in the local safety journal as a `started` event when allowed or a `denied` event when blocked. The preview metadata includes only the operation’s confirmation and allowed flags. No commit text, path contents, token, credential, or remote URL is persisted as preview metadata.

## Verification

The standalone test suite passes with four tests. The preview endpoint was smoke-tested against the current repository and correctly denied a push from the protected `master` branch before any Git push command was run.
